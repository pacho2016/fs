# Подключение заявок FSOCIETY

Форма контактов сохраняет заявки в Supabase. Администратор может просматривать их после входа на `admin.html`. Посетители не могут читать таблицу: это ограничено Row Level Security в базе.

## Настройка проекта

1. Создайте проект Supabase и откройте для него SQL Editor.
2. В Supabase Authentication создайте одного пользователя-администратора. Не включайте публичную регистрацию пользователей.
3. Скопируйте UUID этого пользователя из Authentication и замените нулевой UUID в политике SELECT в `supabase-setup.sql` на UUID администратора. Выполните SQL в редакторе Supabase.
4. В Project Settings найдите Project URL и публичный `anon`/publishable key. Впишите URL, ключ и UUID администратора в `assets/js/supabase-config.js`.
5. Разместите сайт на хостинге с HTTPS и откройте `admin.html`. Входите email и паролем созданного администратора.

В `supabase-config.js` разрешено хранить только публичный anon/publishable key. Никогда не добавляйте туда `service_role` key: он обходит политики доступа и не должен попадать в браузер.

SQL настроен так, что посетители могут только добавлять записи, а читать их может только пользователь с указанным UUID. Не меняйте политику чтения на `using (true)`. Перед запуском замените нулевой UUID в SQL, иначе ни одна учётная запись не сможет читать заявки.

## Проверка

Отправьте тестовую заявку через `contacts.html`, затем войдите в `admin.html` под администратором. Убедитесь, что заявка видна в кабинете, а запрос чтения таблицы без входа запрещён. Если форма показывает ошибку, проверьте URL/ключ в конфигурации и успешное выполнение SQL.

Эта интеграция сохраняет именно заявки с контактной формы; она не создаёт аккаунты для посетителей. Перед сбором реальных персональных данных добавьте доступную посетителям политику конфиденциальности и проверьте соответствие хранения данных требованиям, применимым к вашему сайту.
